# The workspace and the amount of building are separate choices

## Use a finished result

If a person wants the answer, provide the answer through the current supported route. Use an existing outcome skill when available and appropriate; do not assume another skill's presence. No repository, development setup or customization exercise is required. A polished table or ordinary conversation may be the complete result.

## Customize inside the current assistant

Treat an editable artifact, reusable view or host-native workflow as a valid final destination. Preserve the person's visual taste, fields and interaction choices. Offer useful customization without forcing a fixed template or an external app. A host may supply storage, rendering or connectors; inspect those capabilities rather than assuming a product-name match means support.

Chat tools and artifact tools can differ. Qualify the artifact's actual authenticated read path before calling the result connected. A snapshot generated from supplied records is a snapshot. Reopening that snapshot is not a fresh read. Keep private household data out of shared artifact storage or public templates. When a live connection is unavailable, use a snapshot in an established private destination and name the remaining dependency once. If artifact privacy cannot be established, keep private evidence in the existing authorized conversation and use fictional content for the editable layout. A requested refresh can re-read through authorized chat tools and update the snapshot; describe that as a chat-mediated refresh, not an artifact-side live connection.

Do not weaken X1's approval contract to fit a host component. If an artifact cannot perform a required reviewed action, use the supported first-party continuation where available. A direct link must come from the supported workflow, not an invented endpoint.

## Extend an existing project

Respect the codebase, framework, data model and deployment preferences already chosen. Keep source retrieval separate from presentation so the person can replace the view without reconstructing its data access. Supply editable source and a concise run note. Do not add hosting, a new framework or a new data store solely because this skill was invoked.

## Serve clients

A professional may want any of the three modes above. Resolve the actual selected client and allowed operation on every relevant request. A professional title, a broad list of tools or an owned app does not authorize another household. Keep firm-private procedures, household-shared contributions and application preferences distinct.

A hosted client application needs its own reviewed application identity and delegation contract. Do not put a professional's broad token into a client-facing app or claim that installing the builder plugin has qualified that architecture. If current permissions exclude broad graph access for a specialist, preserve that exclusion and use a supported narrower result.

## Handoff

Describe what the person can use now, how to change it if they want to, and the actual source/connection status. A non-builder doesn't need implementation details to use the result. A builder should receive the editable work. Both keep the same evidence and permission boundaries.
