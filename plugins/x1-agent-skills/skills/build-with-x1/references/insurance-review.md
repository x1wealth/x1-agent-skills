# Insurance source review

Make it easier to see what the supplied or authorized records say and prepare a factual question for the person's licensed professional. Keep each policy, currency, source date and source status separate.

## Use it

“Make a dated review list of these policy records and quotes. What does each source actually establish, and what’s the first question I should ask my insurance professional?”

Distinguish an in-force statement as of its stated date from today's status. A quote isn't bound coverage. An explanatory page isn't evidence for a field absent from that page. Don't replace an unknown statement date with upload time.

## Make it mine

“Make this an editable policy shelf in this chat, with the source details easy to open. Let me choose the grouping and fields.”

Preserve the person's visual choices while keeping proposed and evidenced coverage distinct. An attractive layout shouldn't merge currencies, double-count overlapping policies or imply a quote replaced an existing policy. A private snapshot is useful; call it connected only after the relevant read path is qualified.

## Extend my project

“Add dated insurance evidence to my existing dashboard. Keep policy IDs and the current layout. Use authorized X1 reads where useful and keep the read adapter separate.”

Use mounted insurance context and document reads when available, then verify the needed fields in the returned source. A specialist's access to selected policy documents doesn't authorize the entire household graph.

On a later visit, add the new source and explain what changed. Don't infer binding, cancellation, replacement or adequacy. A suitability question goes to the appropriate professional with a useful factual preparation result. Keep the question unsent unless an authorized supported operation is separately requested.
