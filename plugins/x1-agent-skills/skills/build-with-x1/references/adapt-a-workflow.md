# Adapt a different workflow

Begin with the result the person wants and the workspace they already chose. A new recipe doesn't need to resemble a property dashboard.

1. Identify the useful finished result and the moment it will help: a meeting, a recurring review, a new document or a decision. Ordinary questions can be answered directly.
2. Use their existing records and project first. Connect X1 only where an authorized source, supported record state or available action materially helps. A local CSV calculator can stay local.
3. Keep evidence, user assumptions, calculations, working notes and accepted record changes distinguishable. Put app preferences in app state rather than making them household facts.
4. Deliver something usable now. Leave editable source for a builder, an editable host artifact for a customizer, or a finished result for someone who doesn't want to maintain software.
5. On a return visit, observe which earlier work can actually be reused and what still requires manual effort. Preserve failed attempts and simpler-route findings.

For a new professional method, start with the client's permitted evidence and the firm's own authorized procedure. Don't turn the firm's private notes into shared household knowledge. For an investor portal, distinguish the sponsor's records from the investor's household context; delivering a notice doesn't authorize reading that household's other records.

A hosted product needs its own qualified identity, delegation, storage and revocation behavior. The plugin supplies instructions and its supported host connection, not a blanket application-development entitlement. Start with the useful supported handoff instead of inventing a platform.
