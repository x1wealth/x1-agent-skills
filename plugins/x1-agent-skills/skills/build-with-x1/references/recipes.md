# Choose a job, then shape the result

These are starting points. Use the person's own question and existing workflow; don't force a new request into one of these examples. When the necessary files are already supplied, use them directly. Qualify an X1 connection when it helps find or revisit the relevant evidence or carry a supported action forward.

| Job | Useful result | Read when relevant |
| --- | --- | --- |
| Understand a property's records | Parties and roles beside the supporting sources | [Property desk](property-desk.md) |
| Get an entity's bookkeeping evidence ready | Existing checklist enriched with evidence and prepared questions | [Bookkeeping workbench](bookkeeping-workbench.md) |
| Review what's on file for insurance | Dated policy evidence and a factual professional question | [Insurance review](insurance-review.md) |
| Make something else | A small useful result in the person's chosen workspace | [Adapt another workflow](adapt-a-workflow.md) |

Each recipe supports a finished answer, an editable in-host view and an extension to an existing project. The person can move between them. A professional uses the same modes with separately authorized client context; an own-household example doesn't supply client access.

For a return visit, retain the same source references and row identities where useful. Re-read through the supported source path or accept newly supplied records; don't call an old snapshot fresh. Compare setup, finding, checking, refresh and remaining human work against the person's current method. Leave unmeasured effort unmeasured. A local or simpler result is a valid outcome.
